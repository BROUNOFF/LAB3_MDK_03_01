О проекте

Веб-приложение для автоматизации процессов на арктической научно-исследовательской станции. Система обеспечивает строгий учет персонала, контроль за состоянием научного оборудования и дизель-генераторов, мониторинг запасов жизнеобеспечения, а также сбор данных регулярных метеорологических и гляциологических наблюдений.



Технологический стек

Backend: Python + Django.



База данных: PostgreSQL (хранение временных рядов наблюдений, логов калибровки оборудования и складских остатков).



Архитектура: приложение с серверным рендерингом страниц и разграничением доступа на основе встроенной системы авторизации Django.



Как запустить проект локально



Склонируйте репозиторий:



Bash

git clone <URL\_репозитория>

cd polar\_station\_project



Создайте и активируйте виртуальное окружение:



Bash

python -m venv venv

.\\venv\\Scripts\\activate



Установите зависимости:



Bash

pip install -r requirements.txt



Выполните миграции базы данных:



Bash

python manage.py migrate



Запустите сервер разработки:



Bash

python manage.py runserver

Приложение доступно в браузере по адресу \[http://127.0.0.1:8000/](http://127.0.0.1:8000/).



Исходные требования к системе:



1\. Сущности 

Сотрудник: Учетная карточка участника смены.

Прибор: Научное оборудование.

Измерение: Результат снятия показаний с привязкой к дате, времени, прибору и оператору.

Ресурс складского учета: Топливо, продовольствие, медикаменты.

Оборудование жизнеобеспечения: Агрегат с учетом наработанных моточасов.

Нештатная ситуация: Журнал фиксации экстремальных событий с указанием времени, характера и принятых мер.



2\. Процессы

Регистрация смены: Зачисление прибывшего персонала на станцию с указанием их специализации и состояния здоровья.

Фиксация наблюдений: Регулярный ввод данных метеорологической и ледовой разведки специалистами.

Мониторинг приборов и агрегатов: Учет наработки моточасов генераторов и отслеживание календаря поверок научного оборудования.

Складской контроль: Списание ресурсов при их расходе и автоматическое формирование заявки на пополнение.



3\. Роли пользователей и их права

Специалист: Вносит данные наблюдений, фиксирует экстремальные события. Не может изменять данные о калибровке оборудования.

Механик: Отвечает за обновление счетчиков моточасов генераторов, вносит записи о плановом обслуживании агрегатов и калибровке научных приборов.

Врач: Имеет доступ к редактированию полей «состояние здоровья» персонала и мониторингу медицинских запасов.

Руководитель станции: Формирует и координирует расписание дежурств, утверждает сформированные заявки на снабжение, имеет доступ ко всем сводным отчетам. Может просматривать, но не редактировать чужие измерения.



4\. Правила и ограничения

Блокировка оборудования: Если плановая калибровка прибора не проведена в срок, система технически блокирует возможность внесения измерений с использованием данного прибора до ввода акта о калибровке.

Лимиты складов: При снижении остатков любого ресурса ниже установленной нормы, система автоматически генерирует черновик «Заявки на пополнение».

Регламент обслуживания: Плановое обслуживание дизель-генераторов должно инициироваться системой каждые 250 отработанных моточасов.



5\. Отчётность 

Сводка по наблюдениям: Объем выполненных измерений с группировкой по типам и операторам за выбранный период.

Аналитика расхода: Сводный отчет по расходу дизельного топлива, продовольствия и медикаментов в сравнении с нормативами.

Отчет по безопасности: Общее количество зафиксированных нештатных ситуаций и предпринятых мер реагирования.

Штатное расписание: Текущая укомплектованность вахтовой смены в разрезе специальностей.
